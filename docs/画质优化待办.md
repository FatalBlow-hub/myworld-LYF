## 背景与结论

**不换技术栈。** Three.js 在画质方向是优势而非瓶颈——`MeshStandardMaterial`、`shadowMap`、
`EffectComposer`、`SSAOPass` 全是内置的（`three ^0.186.1`），换 Babylon.js 没有本质区别，
换 WebGPU 的收益在 compute 加速网格化、和画质无关。

当前画质不"真实"的 5 个原因（已逐条核对源码）：

| # | 原因 | 定位（按符号，不按行号） |
| --- | --- | --- |
| 1 | 贴图 16×16 + `NearestFilter`，硬边马赛克 | `src/render/Textures.ts` → `createAtlas()` 的 `magFilter` / `minFilter` |
| 2 | 材质是 `MeshLambertMaterial`，无法线/粗糙度/金属度 | `src/render/ChunkMeshCache.ts` → `opaqueMat` / `waterMat` 构造处 |
| 3 | 从未启用 `shadowMap`，画面"平" | `src/render/Renderer.ts` 构造函数（全仓无 `shadowMap` 调用） |
| 4 | 水被烘进 chunk 静态网格，完全没有动画 | `src/render/ChunkMesher.ts` → `meshChunk()` 里 `alphaBlend` 把水推进 `water` 几何数组 |
| 5 | 花是两张固定 45° 交叉片，无随机、无风摆 | `src/render/ChunkMesher.ts` → `emitCross()` |

> ⚠️ 本文档定位一律用**符号名**（函数 / 变量 / 构造处），不写行号 —— `src/` 处于并行改动中，行号必然失效。

**与性能优化的关系**：当前瓶颈在 CPU 网格化；加了阴影之后瓶颈会转到 GPU 填充率。
小岛生存 A 组与联机 M0~M4 均已落地，**画质线现在就可以开工**（渲染层与 M5/M6 的网络层文件正交）。

## 前置决策（已拍板）

- [x] **风格定调：精致像素风**。13 个纹理文件全是 Canvas 程序化画的 16×16 像素画，走写实等于全部重写。
  四条硬约束：
  1. `TILE = 16` 与 `NearestFilter` 不动（改 `LinearFilter` 会糊成一团并造成图集 UV 渗色）
  2. **不引入法线贴图**；水面的波纹高光用着色器里的解析正弦波法线
  3. **主材质保留 `MeshLambertMaterial`**，不换 `MeshStandardMaterial`（没有 IBL/粗糙度贴图时视觉几乎无差别、片元指令却多几倍）
  4. 立体感全部来自**几何光影**（顶点 AO + 面明暗 + 水面高光 + 风摆 + 天空雾 + 软阴影），**13 个贴图文件一行都不改**
- [x] **自动降级：要**。三档 `QUALITY_PRESETS`（HIGH / MEDIUM / LOW），
  **启动期探测 + 运行期帧时间自适应**双保险（`WEBGL_debug_renderer_info` 在新浏览器里已脱敏，单靠它不够）：

  | 参数 | HIGH | MEDIUM | LOW |
  | --- | --- | --- | --- |
  | `pixelRatioMax` | 2 | 1.5 | 1 |
  | `antialias` | true | true | false |
  | `viewDistance` | 4 | 4 | 3 |
  | `shadows` / `shadowMapSize` | true / 2048 | true / 1024 | false / 0 |
  | `bloom` | true | false | false |
  | `ao` / `waterWave` / `windSway` | true（全档常开，开销极低） | true | true |

  探测规则：软渲染关键词（`SwiftShader` / `llvmpipe` / `Software` / `Microsoft Basic Render`）→ LOW；
  移动/核显关键词（`Intel ... HD` / `UHD Graphics` / `Mali-` / `Adreno (TM) [1-5]`）→ MEDIUM；其余 HIGH。
  运行期：最近约 90 帧平均帧耗持续 > 35ms（< 28 FPS）就降一档，切换时按档位表重设
  `setPixelRatio` / `shadowMap.enabled` / Bloom 开关。
- [x] **优先级**：Q0 底座 → T2 AO → T1+T3 → T5 → T4 → T6（可选）。理由见「依赖与开工顺序」。

### Q0 渲染底座（新增）

- **质量档位**：`config.ts` 出 `QualityTier` 与 `QUALITY_PRESETS` 表；`render/Quality.ts` 负责启动探测 + 帧时间自适应；
  `Renderer` 按档位配置 `WebGLRenderer` / 是否开阴影 / 是否开 Bloom。渲染层只依赖 `config`，不反向依赖 `ui`。
- **共享时钟**：`Renderer` 上 `readonly clock = { value: 0 }`，每帧在 `render()` 里
  `clock.value = (performance.now() * 0.001) % 3600`（取模防 float32 精度抖动）；
  `ChunkMeshCache` 构造时接收该对象并在 `clear()` 重建材质后继续复用同一个引用
  （进出大厅会走 `clear()`，材质会重建，uniform 引用必须活过重建）。
- **顶点属性通道**：`ChunkMesher.ts` 的 `GeoArrays` 增加两个通道，`toGeometry()` 无条件写入：
  - `color`（vec3）：AO × 面明暗的亮度系数
  - `aEffect`（float）：**逐顶点特效权重**，语义由材质解释——
    `opaqueMat` → 植物风摆权重（0 = 不动，1 = 顶端）；`waterMat` → 液面波动权重；`glowMat` → 恒 0
  材质侧用 `onBeforeCompile` 注入，**必须各自设置 `customProgramCacheKey`**（如 `'voxel-water-v1'` /
  `'voxel-opaque-sway-v1'`），否则会被 three 的 program 缓存与普通 `MeshLambertMaterial` 串味。

### T1 水面动起来（与 T3 同批）

- **现状**：水在 `meshChunk` 里和方块一起烘成静态几何；`waterMat` 只有 `transparent` + `depthWrite:false`。
  该材质**由所有 `alphaBlend` 方块共用**（水、玻璃、冰、五种泽液、喷泉水面），改动必须只作用于液面。
- **做法**：新建 `render/WaterMaterial.ts` 封装 `createWaterMaterial(texture, clock)`：
  - 顶点着色器：按世界坐标 `xz` + `clock.value` 叠 2 个正弦波，只对 `aEffect > 0`（液面顶点）位移，振幅约 0.03 格
  - 片段着色器：液面顶点两层滚动 UV → 解析法线扰动 + Blinn-Phong 高光（`pow(max(dot(N,H),0),48)`）+ 淡淡菲涅尔，
    玻璃/冰 `aEffect == 0` 走原样
  - 保留 `transparent` + `depthWrite:false`，不动现有透明排序；液面顶点标记在 `meshChunk` 里打
    （**必须覆盖 `WATER` 与五种 `SWAMP_*`，以及喷泉的 `FOUNTAIN_WATER`**；只有暴露在空气/水面上方的顶面才打标）
- **收益**：水从"一块蓝板"变成"会动的水"，视觉提升最大。**风险**：低，但漏标/误标会表现为"玻璃跟着晃"或"泽液不动"。

### T2 环境光遮蔽 AO

- **做法**：`meshChunk` 主循环的完整方块面按每个顶点周围 3 个邻居（两侧 + 角落，邻居用现成的 `opaqueCube()` 判定）
  算遮挡，查表 `AO_CURVE = [1.0, 0.82, 0.65, 0.5]`，再乘面方向明暗（顶 1.0 / ±z 0.86 / ±x 0.76 / 底 0.6），
  一起写进顶点色；三个材质都开 `vertexColors: true`。
- **两条硬约束（审核提出、我采纳）**：
  1. `pushQuad` 加可选参数（AO 数组 + 面明暗，默认全白/1），并在 `ao[0]+ao[2] < ao[1]+ao[3]` 时**翻转三角剖分**，
     否则会出现体素 AO 经典的对角线黑三角伪影；带默认值可让 `emitCross` / `emitPlainBox` 不改调用处
  2. **不做顶点法线插值平滑**（会把方块变成圆滚滚的充气枕头）；平滑感由 4 顶点顶点色插值天然得到
- **范围收敛**：第一版只给完整方块面做逐顶点 AO；异形方块（`emitBox` 路径）只给面明暗，不做邻居 AO；
  `glow` 方块顶点色恒为白（保持夜里满亮）。
- **顺带修 Bug**：异形分支改 `emitBox(def.glow ? glow : solid, ...)`，让 `CARPET_STAR` / `BED_STAR` 回到发光材质。

### T3 植物随机化与风摆

- **做法**（两项，删掉原「多层花瓣」）：
  1. `emitCross` 按世界坐标哈希（`wx` / `wz` 确定性哈希）随机旋转角 + 水平微移，**不越出格子 AABB**
     （否则射线拾取与高亮框会对不上）；**随机高度 0.82~1.0 只给 `TALL_GRASS` / `DANDELION` / `POPPY` / `SEAWEED`**，
     农作物与竹笋一律原高度（靠高度判断熟没熟）
  2. 顶点着色器按 `clock.value` + 世界坐标相位摆动，**摆幅由 `aEffect` 权重控制**：
     `emitCross` 底边顶点写 0、顶边顶点写 1 → 根茎钉死在土里/水里，只有上半截摆；水稻/泽生植物自然"越矮摆得越轻"
- **收益**：花草"活"过来，草丛、水稻、作物一起受益。**风险**：低。**不再有排期约束**（小岛 A7 早已上线）。

### T5 天空与雾

- **现状**：纯色 `scene.background` + `THREE.Fog(0x87ceeb, 40, 90)`，`camera.far = 200`。
- **做法**：
  - 反面渲染的天空球（半径约 150，`side: BackSide`、`depthWrite: false`、`fog: false`），
    uniform 三组颜色：天顶色 / 地平线色 / 太阳方向；`setDaylight(k)` 里做三段插值
    （白天深天蓝→浅青蓝、黄昏/黎明地平线泛暖橙、深夜深蓝黑）
  - **雾保留线性 `THREE.Fog`**，`near/far` 与视距绑定（`near ≈ 视距×16×0.65`、`far ≈ 视距×16×1.1`）；
    雾色**必须等于天空球地平线色**，远处区块切面才会无缝融进地平线
  - 天空球每帧跟随相机水平坐标（`SPAWN.RANGE = 20000`，不能钉在原点）
- **收益**：天空与远景观感提升明显。**风险**：低。

### T4 阳光阴影

- **前置结论：不需要子区块拆分**（`T4-pre` 已删除）。正交 shadow camera 由玩家坐标决定，与区块包围盒无关。
- **做法**：
  - `renderer.shadowMap.enabled`（按档位）+ `PCFSoftShadowMap`；`sun.castShadow`（夜里 `setDaylight(k)` 里 `k` 过低时关掉省 GPU）
  - `scene.add(sun.target)`；正交相机覆盖玩家周围约 40~48 格（`2048` 档位约 25 texel/格）、`near ~10` `far ~160`
  - `sun` 与 `sun.target` **按玩家整格坐标跟随**（纹素对齐，避免走路时阴影边缘闪烁）；`bias ≈ -0.0005`、`normalBias ≈ 0.03` 防摩尔纹
  - 区块网格 `castShadow` / `receiveShadow` 全开；**水面只 `receiveShadow`、不 `castShadow`**（否则湖面投出一块实心黑影）
  - `entities/`（`Animal`、`Zombie`、`Tank`、`ItemDrop`）身体部件开 `castShadow`，否则活物"飘"在地上
  - 实现时**必须验证花草/树叶/梯子在阴影里不是实心方片**（`opaqueMat` 带 `alphaTest`，且 T3 给它挂了风摆注入，
    必要时配 `customDepthMaterial`；此项存疑，冒烟确认后记录结论）
- **收益**：画面层次感最大来源。**风险**：中，性能翻倍消耗，必须配质量档位。

### T6 后处理（可选，仅 HIGH 档）

- **砍掉** `Reflector`（多高度水体不适配）与 `SSAOPass`（`overrideMaterial` 会毁掉 `alphaTest` 花草与半透明水面，
  且 T2 顶点 AO 已覆盖其收益）。
- **只留轻量 Bloom**：`EffectComposer` + `RenderPass` + `UnrealBloomPass` + `OutputPass`（都在已安装的 `three` 内，不新增依赖）；
  `threshold ≈ 0.88`、`strength ≈ 0.35`、`radius ≈ 0.3`；`glowMat` 调成略大于 1 的 HDR 颜色，让白天雪地/沙子不过曝；
  **创建 RenderTarget 必须带 `samples: 4`**，否则接入后处理会丢掉全局 MSAA。

## 依赖与开工顺序

```
Q0 质量档位 + 共享时钟 + 顶点通道
  ├─→ T2 AO（纯 CPU 网格化，零 GPU 负担，性价比最高）
  ├─→ T1 水面波浪 ─┬─→ T3 植物风摆（同批做，共用时钟与注入机制）
  │                └─→ T6 Bloom（需先有 T4 的发光体系与档位）
  ├─→ T5 天空与雾 ─→ T4 阴影（复用 T5 理顺的太阳方向与相机跟随）
  └─→ （T3 无排期约束：小岛 A7 已上线）
```

顺序理由：① 先立档位与时钟底座，后面所有特效的开关与动画都依赖它；② T2 不动着色器、立刻见效；
③ T1 与 T3 都改 `ChunkMeshCache` 的材质构造与 `clear()`，**同批做避免反复改同一处**；
④ T5 先把 `Renderer` 的昼夜颜色、太阳方向、相机跟随理顺，T4 顺势复用。
