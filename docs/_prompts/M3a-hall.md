# M3a — 大厅场景与场景切换（小岛生存 B1 B11 前半）

## 目标

加一个**大厅场景**：按 `H` 键在自己的岛与大厅之间来回切换。大厅是一张固定的木板平台（中间放需求里描述的那张桌子），四周有边界出不去，里面没有怪物动物。自己的岛进度自动保存，回岛后原样恢复。

> 本里程碑只做「场景 + 切换」。排队、匹配、扣 2 铁锭、好友岛都是后面 M3b/M4 的活，**本期一律不做**。

## 已拍板的决策（照做）

| 项 | 决策 |
| --- | --- |
| 入口键 | `H` 键（`config.ts` 的 `KEYS` 加 `hall: ['KeyH']`） |
| 大厅地图 | 固定 16×16 木板平台（一个区块大小），**中间放桌子**：底层 3 格——左右各一格木板、中间空；第二层填满 3 格木板 |
| 边界 | 平台四周一圈**栅栏**（复用现有 `FENCE`，可见、零成本），玩家走不出去；平台下方是空的，掉下去由虚空规则处理（复用现有 `VOID_Y` 重生逻辑即可，不用特殊照顾） |
| 大厅内容 | 无怪物、无动物、无掉落物（切换时清空）；昼夜照常（不用特殊处理） |
| 进大厅流程 | ①先 `saveNow()` 把岛存好 → ②清空当前世界与活物 → ③生成大厅世界 → ④玩家传送到大厅出生点（平台中央，桌面高度 +1） |
| 回岛流程 | 再按 `H` → 重新读当前档（`applySave`）→ 世界/背包/位置/血量全部恢复成进大厅前的样子 |
| 背包 | 随身背包跨场景携带（进大厅不停背包，回岛后自然还是同一份——因为存档里存的就是它） |
| 联机 | **本期不接服务端**（纯本地切换），M3b 再接 |

## 允许改动的文件

- `src/config.ts` —— `HALL` 常量段（尺寸、出生点、桌子位置）
- **新增** `src/world/HallMap.ts` —— 生成大厅世界（平台 + 桌子 + 栅栏边界），导出 `buildHall(world)` 一个函数
- `src/world/World.ts` —— 加清空/重置方法（区块、箱子、熔炉、朝向表全清）
- `src/render/ChunkMeshCache.ts` —— 加清空方法（换场景时旧网格要全部 dispose）
- `src/core/Game.ts` —— `enterHall()` / `leaveHall()`、`H` 键处理、切换时活物与掉落物清空
- `src/ui/Hud.ts` —— 进出大厅各提示一次（复用 `showMessage`）

## 禁止

- 不改 `docs/` 下任何文件
- 不动 `server/data.db`、真实账号存档；场景切换会写 localStorage 存档是正常游戏行为，允许
- 不新增 npm 依赖
- 不做排队/匹配/扣费/好友岛/联机（本期是纯本地场景切换）
- 不改玩法核心逻辑（挖/放/物理/饥饿都不动）

## 现有代码约定（必须遵守）

1. **依赖铁律**：`ui / interact / player → render / world → config`；`world` 不许反向依赖上层
2. **文件 ≤500 行**；注释中文、代码英文；新模块顶部写"模块名 + 一句话职责"
3. **世界生成照 `TerrainGen` 的区块写法**（`world.ensureChunk` / `chunk.data[i] = ID`），大厅就一个区块，直接填
4. **网格清空要连材质一起 dispose**（照 `ChunkMeshCache` 现有 rebuild 里的 dispose 写法）
5. **切换时把 `mobs` / `drops` / `potions` / `vehicles` 等活物一起清掉**（回岛时 `applySave` 会还原，别漏）

## 验收标准

1. `npm run build` 通过（tsc 零报错）
2. 按 `H`：HUD 提示「来到大厅」，看到 16×16 木板平台 + 中间那张桌子，自己站在桌上/桌边，四周栅栏走不出去
3. 大厅里没有僵尸动物；按 `9` 开背包正常；挖/放方块正常
4. 再按 `H`：回到自己的岛，**位置、背包、血量、饥饿、岛的类型都和走之前一致**，之前挖过的坑/盖的房子还在
5. 来回切换 5 次不报错、不白屏、不掉帧
6. 切到大厅后按 `1` 存档再刷新：进的是岛（不会卡在大厅里出不来）
