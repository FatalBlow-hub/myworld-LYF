## 二、账号系统与服务端存档

后端选型：**纯 Node + `better-sqlite3`，零框架**，数据全在 `server/data.db` 单文件（`server/index.mjs` 头注释与 `DB_FILE`）。

| 决策 | 取值 / 做法 | 出处 |
| --- | --- | --- |
| 开放注册 | 名字 2~16 位 + 密码 | 变更历史 |
| 总量上限 | `MAX_USERS = 500`，满了返回 403「人满了，找站长加位置」 | `server/index.mjs:37,184` |
| 防猜密码 | `AUTH_LIMIT = 20` 次 / IP / 分钟（登录注册） | `server/index.mjs:39,166` |
| 其他接口限流 | `API_LIMIT = 120` 次 / IP / 分钟 | `server/index.mjs:40,209` |
| 存档模型 | **一个账号一档** → `user_id` 即存档表主键 | `server/index.mjs:58` |
| 旧档处理 | 自动进 `backup` 列 | 变更历史 |

前端这侧的核心是 `src/ui/Auth.ts` 的 `probeAuth()`，它把「后端在不在」抽象成三态：

- `'off'` —— 后端没跑（含断网），**自动退回老的本地 3 槽位菜单**
- `{ name: 'xxx' }` —— 已登录
- `{ name: null }` —— 后端在但没登录，弹登录框

这个三态设计是当天最重要的一个决定：**后端挂掉不影响玩**，只是退回单机模式，
而不是白屏或卡在登录页。开发时 vite 把 `/api` 代理到 8787，本地与线上同一套路径。

## 三、部署上云

| 项 | 值 |
| --- | --- |
| 主机 | 腾讯云 `49.235.124.163`，`ssh tencent` 直连 |
| 站点目录 | `/www/wwwroot/minecraft-web/` |
| 进程 | systemd 服务 `minecraft-web`（开机自启 + 崩溃重启），**只听 `127.0.0.1:8787`** |
| 对外 | Nginx 反代 → `https://ms.7shu.asia` |
| 数据迁移 | 本地账号库（尧婷婷）已迁入服务器 `data.db` |
| 清理 | 本地 `saves/`、快照、playwright 临时文件已清除 |

**同日拍板：去掉 `saves/*.json` 双写。** 账号系统刚落地时是「SQLite + 肉眼可读的 `saves/<账号>.json` 双写」，
上云时砍掉双写，存档只进 SQLite —— 双写意味着两份数据会漂移，而服务器上的 json 也没人去肉眼看。

两条**不可违反的部署约束**（写进了 `PROJECT_CONTEXT.md`，后续任何人部署都要遵守）：

1. **证书 / 防火墙别碰** —— 由管理员配，改动会让站点直接不可达
2. **手机版域名必须用一级子域** —— 证书是 `*.7shu.asia` 通配（Let's Encrypt，**2026-12-14 到期**），只覆盖一层；
   `m.ms.7shu.asia` 这种三层域名会被浏览器判证书不匹配。手机版走 `m.7shu.asia` 加一条 A 记录 + 一个 `server_name` 反代到同一个 8787 即可，
   **不需要第二份代码或第二个 html**

一键部署用 rsync，排除 `node_modules/dist/.git/.playwright-mcp/saves/快照/server/data.db*`，**不覆盖线上存档**；
验证方式是 `ssh tencent 'curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:8787/'` 回 200。

## 四、手机触屏

判定入口（10-14 当时的版本，在 `src/ui/TouchControls.ts`）：

```ts
export function isTouchDevice(): boolean {
  return navigator.maxTouchPoints > 0 || location.search.includes('touch=1');
}
```

`?touch=1` 是强制开关，方便在电脑上预览手机版。

虚拟按键层布局：

- **左下摇杆** —— 前 / 后 / 左转 / 右转（等价于按住方向键）
- **右侧** —— 挖（按住连挖）/ 放 / 用 / 跳 / 降 / ▲▼ 看
- **底排** —— ◀ 吃 包 ▶
- **顶排** —— 书 / 存 / 家 / 尸 / 停

配套细节：四个面板（背包 / 箱子 / 染色 / 收集册）加「点空白处关闭」；手上物品图标跟手指走；竖屏时提示横过来。

**关键架构决策：所有按钮经 `Controller.press()` / `release()` 走原键盘管线**（`TouchControls.ts` 里成对出现）。
没有为手机新写一套输入系统 —— 手机和 PC 共用同一条输入管线，只是「按键的来源」从键盘事件换成指针事件。
这个选择让触屏层保持在很薄的一层，后续加按键不需要动玩法代码。

## 五、修「合成不出来」

这是个长期存在、手机端被放大的缺陷。

**根因**：合成配方要求格子里的数量和配方**一分不差**，但此前物品只能整摞放 / 整摞拿
（唯一的拆分是键盘 `K` 键，且只能往储物格分）。手机上没有右键也没有 `K`，根本没法凑数 —— 配方看得见做不出来。

**修法**：所有物品格支持**右键（电脑）/ 长按 400ms（手机）** → `Inventory.clickOne()`（`src/player/Inventory.ts:133`）：

- 手上捏着东西 → 只放 1 个
- 空手 → 拿起半摞

两个边界处理：长按后浏览器合成的假 `click` 会被吞掉（防连点）；桶装液体仍整桶走、不拆分。
适用范围是通用格子：背包 / 工作台 / 箱子 / 熔炉。

## 六、当前结论

### 架构共识

1. **账号 = 存档的唯一维度** —— 一个账号一档，`user_id` 直接当主键，不做多档位
2. **后端是可选的** —— 前端必须能在 `'off'` 态完整运行，`probeAuth()` 三态是这套契约的载体
3. **输入只有一条管线** —— 任何新输入设备（触屏、手柄）都收敛到 `Controller.press/release`，不新增玩法分支
4. **部署只反代 8787** —— 手机版 / PC 版共用同一份代码与同一个端口，靠域名区分

### 技术债务

- **存档单点**：去掉 json 双写后，`data.db` 成了唯一副本，目前没有离线备份策略
- **限流是内存计数**：`AUTH_LIMIT` / `API_LIMIT` 的计数随进程重启清零，只能防普通暴力试探
- **`MAX_USERS = 500` 是硬编码**：人满要改代码重启，没有后台调整入口
- **触屏判定偏简单**：10-14 只有「设备触屏 + `?touch=1`」，没有手机版域名维度

### 风险提示

- **证书 2026-12-14 到期** —— `*.7shu.asia` 通配证书只覆盖一级子域，到期前需续签并验证；
  新增任何手机版域名都必须是一级子域，否则浏览器报证书不匹配
- **线上存档无备份** —— 一键部署脚本刻意排除了 `data.db`（正确），但若主机故障则账号与存档一起丢失
- **本地与线上两套存档会分叉** —— 本地模式玩的进度不会自动上云，用户容易困惑「我的档去哪了」
