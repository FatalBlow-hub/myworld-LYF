## 二、技术调研结论

当日三次问答定方向，结论如下（详见「待定与未决」of `docs/画质优化待办.md`）：

### 2.1 技术栈认知纠偏

用户最初以为游戏是"纯 CSS 渲染"，并问"换 React 组件是不是效果更好"。

| 问题 | 结论 |
| --- | --- |
| 是纯 CSS 渲染吗 | ❌ 3D 世界是 Three.js/WebGL 走 GPU；CSS 只管 `index.html` 里那层 2D 覆盖层（HUD/菜单/背包面板） |
| 换 React 会更好吗 | ❌ 3D 帧循环 React 管不着；HUD 用 `lastHotbarSig` 签名比对跳过重绘，比每帧 `setState`→reconcile 更省；只有背包/合成/染色面板层有讨论价值，但当前 10 个 UI 文件共约 1300 行、最大 118 行，未失控 |

**替代方案**：面板状态若真到难维护，性价比更高的做法是抽一个极小的订阅式 store，而非引入框架。

### 2.2 性能优化路线：换框架不解问题

定位到 5 个瓶颈，**全部在 CPU/架构层，与渲染库无关**：

1. 区块是 16×64×16 整柱，`meshChunk` 全高 64 层扫，改一格重扫 16384 格
2. `rebuildDirty()` 无预算，一帧把脏队列全做掉
3. `streamChunks(Infinity)` 开局同步生成 81 个区块
4. 柱子包围盒巨大 → 视锥剔除失效，约 200+ draw call 常驻
5. 实体未合批，动物/僵尸多 Mesh 拼装、掉落物各带材质

三路线对比后推荐 **A 原地优化**：

| 路线 | 收益 | 成本 |
| --- | --- | --- |
| A 原地优化（子区块/脏队列预算/分帧/实例化） | 最大 | 1–3 天，零迁移风险 |
| B 换渲染后端（WebGPURenderer / Babylon） | 小——瓶颈在 CPU | 中，API 迁移 |
| C 重写（Rust + wgpu + WASM） | 天花板最高 | 周级，等于重做 |

### 2.3 画质路线：不换栈，走「几何光影」

用户澄清没有卡顿、目标是画质后转向此线。核心判断：**Three.js 在画质方向是优势**，`MeshStandardMaterial` / `shadowMap` / `EffectComposer` / `SSAOPass` 全内置，换 Babylon 无本质区别、换 WebGPU 与画质无关。

同时回答了「无显卡机器」的三种情况（集显能跑 / 关硬加速走 SwiftShader 掉到 5–15fps / 虚拟机可能起不了上下文），由此**决定必须做自动降级**。

### 3.2 关键技术决策

**决策 1：先审核后实现**。方案写完后先用 `docs/_prompts/Q1-graphics-review.md` 交 auggie 做**只读**审核（-a 禁止改文件），报告 `_auggie/out/Q1-review.md`（未入库）。审核提 12 条，采纳 10、**修正 2**：

| # | 审核结论 | 处置 |
| --- | --- | --- |
| 2 | 用 `fract(transformed.y) > 0.01` 区分液面与玻璃/冰 | ❌ 改**显式逐顶点 `aEffect`**。五种 `SWAMP_*` 泽液顶面同为整数高度，会被判成玻璃而永远静止 |
| 5 | `uTime` 在 `rebuildDirty()` 首行更新即可 | 🟡 改 `Renderer` 持有时钟并在 `render()` 推进。`Game.tick` 只在 `!paused` 调 `rebuildDirty`，暂停/开面板时动画会冻住 |

**决策 2：删除 `T4-pre` 子区块拆分**。正交阴影相机由玩家坐标决定、与区块包围盒无关；拆成 16³ 反而让 Draw Call 从 ~81 涨到 180+，且地底实心层已被 `opaqueCube` 面剔除掉。**这条推翻了我前一天的判断。**

**决策 4：`Game.ts` 零新增行**。实测已 474 行逼近 500 红线，新渲染逻辑一律进 `render/` 层（新增 `render/Quality.ts`、`render/WaterMaterial.ts`），`Game.ts` 只允许改现有行。

## 六、当前结论

### 架构共识

- **依赖铁律维持**：`ui / interact / player → render / world → config`，渲染层的质量档位只依赖 `config`，不反向依赖 `ui`
- **新逻辑进 `render/` 层**，`Game.ts` 只改现有行（474/500 红线）
- **渲染约定**：所有材质 `onBeforeCompile` 注入必须各带 `customProgramCacheKey`（如 `'voxel-water-v1'`），否则与普通 `MeshLambertMaterial` 串 program 缓存
- ** LLMs 定位一律符号名**，不写行号
